# 全語音輸入：三層架構

| 層 | 做什麼 | 狀態 |
|---|---|---|
| 第一層 | 全語音輸入：自動收音 → 切句 → 轉寫 → 貼進游標所在的輸入框 | 已完成 |
| 第二層 | 跟 Typeless 一樣：轉寫稿加上上下文，經過 AI 整理、改寫再貼上 | 要做 |
| 第三層 | 不用先點輸入框：自動找到對的輸入框並寫進去 | 要做 |

```
            ┌─────────── 第一層（現在）──────────────────────────────┐
麥克風 ──▶ 本機切句 ──▶ 轉寫（gpt-transcribe＋專有名詞）──────────────┼──▶ 貼上
            └──────────────────────────────────────────────────────────┘
                         │                                         ▲
            ┌──── 第二層 ─▼─────────────────────────────────────┐   │
            │ 段落判定 ──▶ AI 編輯（轉寫稿＋上下文＋個人設定）──┼───┤
            │       ▲                                          │   │
            │  開口時抓上下文：app、視窗、網址、游標前後、選取  │   │
            └──────────────────────────────────────────────────┘   │
            ┌──── 第三層 ───────────────────────────────────────┐   │
            │ 游標不在輸入框 → 找候選輸入框 → 排序 → 對焦 ───────┼───┘
```

## Typeless 怎麼做（查證過的）

**官方說法**（[官網](https://www.typeless.com)、[隱私權政策](https://www.typeless.com/privacy)）：
- 語音和「有限的上下文，例如你正在用的 app，以及裡面相關的文字」，即時送到雲端處理後丟棄。
- 會把語音與相關文字送給第三方雲端 AI（Microsoft、Google），並宣稱對方也零保留。
- AI 層的功能：
  - 清理：去贅字、去重複；講到一半改口時只留最後的意思；把講出來的清單、步驟排成條列。
  - 個人化：依 app 調整語氣（聊天輕鬆、email 正式、文件精簡）；個人字典可以自動學，也可以手動加。
  - 語言：支援 100 多種語言，可以混著講。
  - 選取文字後的操作：用講的改寫（變短、變正式）；對選取的文字提問（摘要、解釋、翻譯）。
  - 其他：邊講邊翻譯；歷史存在本機。

**反向工程的說法**（[競品 Voibe 的文章](https://www.getvoibe.com/resources/typeless-privacy-issues/)，未經證實）：Typeless 透過 macOS 的輔助使用 API 抓瀏覽器網址、焦點 app 名稱、視窗標題，也會要求螢幕錄影權限；語音送到 AWS us-east-2。

**歸納：** Typeless 就是「語音轉寫」加上「一層 LLM 編輯」。LLM 拿到轉寫稿、上下文（app、視窗、網址、欄位裡的字、選取）和個人設定（語氣、字典），輸出要寫進去的字。下面第二層照這個做。

## 第一層：全語音輸入（已完成）

`bin/listen.mjs` 的流程：
1. ffmpeg 收音（24kHz）。
2. 本機判斷人聲，停頓 0.85 秒切成一句。
3. 轉寫：OpenAI `gpt-transcribe`，帶專有名詞（keywords）與 `zh-tw`；也可以換 `local` 或 `parallelsandbox`。
4. 轉成台灣正體，套固定替換。
5. `bin/paste.js` 確認游標在輸入框，再貼上。

選單列小程式負責權限、狀態與暫停（`app/ui.js`）。

## 第二層：AI 編輯層（跟 Typeless 一樣）

### 流程

1. **開口時就抓上下文**（跟收音同時進行，不拖時間）。以下都在這台實測讀得到，用現有的輔助使用權限就夠，不需要新權限：
   - 最前面的 app（bundle id、名稱）、視窗標題。
   - 瀏覽器網址：Chrome、Arc 用 AppleScript，要多一個「自動化」權限；或改讀網址列的 AX 值。
   - 輸入框：角色、標籤或提示字（例如 Claude 的「Prompt」）、游標前 N 字、游標後 N 字、選取的文字。
   - （選配，預設關）同一視窗附近的內容，例如聊天室上面幾則訊息。用網頁的 `AXUIElementsForSearchPredicate` 抓，實測 Claude 視窗 100 個文字元素只要 5 ms。
   - 密碼欄位（`AXSecureTextField`）和排除清單裡的 app 不抓、不送。

2. **整段講完才送 AI。** 講到一半改口要看整段才知道，所以切法分兩層：
   - 「句」：停頓 0.85 秒（現在的做法），先送去轉寫。
   - 「段」：停頓超過 1.8 秒（可調），或換了 app，或按了暫停，才算一段。
   - 一段結束時，大部分句子已經轉好，只差最後一句，然後整段一起送 AI。

3. **AI 編輯**（快速模型，例如 Claude Haiku 5.5 或 OpenAI 的 mini 級）：
   - 輸入：固定規則、這個 app 的語氣設定、個人字典、上下文、整段轉寫稿。
   - 輸出 JSON：`{ "mode": "insert" | "replace_selection" | "command", "text": "...", "command": "..." }`
     - `insert`：整理後的字。去贅字、去重複、只留改口後的意思、條列排版、補標點、依 app 調語氣、配合游標前後文（例如接在半句話後面就不重複主詞、不加句首大寫）。
     - `replace_selection`：有選取文字，而且講的是指令（「改正式一點」「縮短」「翻成英文」），就改寫選取的字。
     - `command`：「換行」「刪掉剛剛那句」「全部清掉」。「送出」預設關閉。

4. **寫入：**
   - 插入或取代都用貼上；有選取時 Cmd+V 就會取代選取。
   - 原文留著，選單加「換回原文」，把剛貼的 AI 版換回轉寫原文。

5. **自動學個人字典**（Typeless 的「自動學」）：
   - 貼上 30 秒後再讀一次那個欄位，比對使用者自己改了哪些字。
   - 同一個改法出現兩次，就加進專有名詞或替換表（選單裡可以看、可以刪）。

### 延遲

講完一段停 1.8 秒判定結束，接著：
- 最後一句轉寫：約 0.6–1.3 秒。
- AI：約 0.4–1.2 秒，用串流。
- 貼上：約 0.3 秒。

合計大約停下後 3–4 秒出字。要更快，可以把段落停頓調短，或只在長句、或有選取時才走 AI。

### 設定（`config.json` 新增）

```json
{
  "ai": {
    "enabled": true,
    "provider": "openai",
    "model": "",
    "segmentPauseMs": 1800,
    "contextChars": 400,
    "nearbyContent": false,
    "styles": {
      "com.tinyspeck.slackmacgap": "口語、簡短",
      "com.apple.mail": "正式、完整句子",
      "com.anthropic.claudefordesktop": "精準的指令，保留技術名詞"
    }
  }
}
```

## 第三層：自動找對的輸入框

### 3a：同一個視窗裡自動對焦

游標不在輸入框時（例如剛點了訊息列表、在看網頁）：

1. **找候選：**
   - 網頁和 Electron app 用 `AXUIElementsForSearchPredicate` 加 `AXTextFieldSearchKey`（實測 Claude 視窗找到 2 個輸入框，2 ms）。
   - 原生 app 走 AX 子元素樹。
2. **排序：**
   1. 這個視窗上次用過的輸入框。
   2. app 專屬規則：Claude／ChatGPT 的 Prompt、Slack 的訊息框、Gmail 的內文、終端機。
   3. 畫面上最下方、最大的可編輯框（聊天輸入框的慣例）。
   4. 只有一個候選就用它。

   搜尋框、密碼框預設排除。
3. **對焦：** 把那個輸入框設成 `AXFocused = true`（必要時先把視窗拉到前面），再寫入；選單列閃一下「→ 寫進 Prompt」。
4. **信心不夠就不動：** 不寫入，原文留在「複製上一句」。

### 3b：用講的指定要寫到哪裡（跨 app）

例句：「在 Slack 跟 Jason 說明天開會改三點」「回覆這封信：好的，週五前給你」。

1. AI 從句首拆出「目標 app／對象」和「內容」；句首沒有這類指定詞就不觸發。
2. 切到目標 app → 用那個 app 的專屬導航（URL scheme、AppleScript、按 AX 按鈕）找到對象 → 對焦輸入框 → 寫入。
3. 永遠不自動送出。

這已經是半個代理人，每個 app 都要寫一個轉接器，所以先做 3a，3b 從最常用的兩三個 app 開始。

## 程式怎麼拆（對照現在的檔案）

| 檔案 | 改什麼 |
|---|---|
| `bin/listen.mjs` | 改成一條管線：收音 → 切句 → 轉寫 → **段落** → **上下文** → **AI 編輯** → **找目標** → 寫入 |
| `bin/ax-agent.js`（新） | 常駐的 JXA 程序，用 stdin／stdout 傳 JSON：讀上下文、找輸入框、對焦、寫入、事後讀回。取代每句都開一次 osascript，每句省 100–200 ms |
| `bin/editor/`（新） | 呼叫 LLM（OpenAI、Anthropic）、組 prompt（規則、app 語氣、字典）、驗證 JSON 輸出 |
| `bin/targeter.mjs`（新） | 候選輸入框排序與各 app 的專屬規則 |
| `bin/history.mjs`（新） | 本機歷史：原文、AI 版、app、時間；給「換回原文」和自動學字典用 |
| `app/ui.js` | 選單加：AI 編輯開關、換回原文、目前的寫入目標、歷史 |
| `tests/` | 用假的 LLM 測 AI 編輯、用假的 AX 樹測找目標、測段落判定 |

## 跟 Typeless 的功能對照

| Typeless 功能 | 我們在哪一層 | 做法 |
|---|---|---|
| 在任何 app 講話就打字 | 第一層 | 已完成（我們不用按鍵，自動收音） |
| 專有名詞、個人字典 | 第一層＋第二層 | 已有詞彙表；第二層加上自動學 |
| 去贅字、去重複、改口只留結果 | 第二層 | AI 編輯，整段一起處理 |
| 條列排版、補標點 | 第二層 | AI 編輯 |
| 依 app 調語氣 | 第二層 | `ai.styles` 依 bundle id 設定 |
| 配合游標前後文 | 第二層 | 上下文的游標前後 N 字 |
| 選取文字用講的改 | 第二層 | `replace_selection` |
| 對選取的唯讀文字提問（摘要、翻譯） | 第二層延伸 | 結果顯示在選單列面板，不寫入 |
| 邊講邊翻譯 | 第二層 | `ai.translateTo` 設定，或用講的切換 |
| 100 多種語言混講 | 第一層 | `gpt-transcribe` 本來就支援 |
| 歷史存本機 | 第二層 | `history.mjs` |
| 自動找輸入框、指定 app | 第三層 | Typeless 官網沒提到自動對焦，這部分是我們多做的 |

## 分階段

| 階段 | 內容 |
|---|---|
| M1 | 第二層核心：段落判定、上下文、AI 清理、依 app 語氣、換回原文 |
| M2 | 用講的改選取文字、語音指令、個人字典自動學、歷史 |
| M3 | 第三層 3a：同視窗自動對焦 |
| M4 | 第三層 3b：跨 app 指定目標、翻譯、對選取文字提問 |

## 待決定

1. AI 用哪家：OpenAI（跟轉寫同一把 key，最簡單）或 Anthropic（Claude Haiku 5.5）。
2. 停多久算一段講完：建議 1.8 秒。越短出字越快，但越容易把一段話切斷。
3. 要不要抓「同視窗附近的內容」：AI 會更懂前後文，但送出去的資料也更多。
4. 3b 先支援哪幾個 app。
